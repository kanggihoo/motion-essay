# motion-essay

**백엔드 내부 동작과 그것이 실패한 실제 사건을, 스크롤로 시간 축을 이동하며 설명하는 인터랙티브 웹 에세이.**

방문자가 스크롤을 내리면 사건이 흐르고, 올리면 되감긴다. 시간을 조종하는 건 제작자가 아니라 방문자다.

---

## 왜 이걸 만드는가

BE 중심으로 개발해 왔고 FE는 "데이터를 보여주는 용도"로만 써봤다. 이번엔 모션과 인터랙션이 결과물의 핵심인 걸 만든다. 목적은 서비스가 아니라 **링크 하나로 역량을 보여주는 것**이다.

소재를 "백엔드 + 장애"로 잡은 이유 네 가지:

1. **모션이 장식이 아니라 설명이 된다.** 장애와 프로토콜은 본질적으로 시간 순서다. 모션을 빼면 설명이 무너진다. 브랜드 사이트에서 모션은 빼도 정보가 남는다 — 그 차이가 포트폴리오에서 크다.
2. **디자이너 안목을 요구하지 않는다.** 기술 다이어그램의 기준은 "예쁜가"가 아니라 **"명료한가"**다. 명료성은 규칙(대비·정렬·한 번에 하나만 강조)으로 달성되고, 미감은 규칙으로 안 된다.
3. **BE 정체성을 버리지 않는다.** 순수 FE 역량으로 FE만 판 사람과 겨루면 불리하다. 이건 **FE 역량으로 BE 깊이를 전시**하는 거라 경쟁자가 적다. BE 면접관은 내용에, FE 면접관은 구현에 반응한다.
4. **글감이 공짜로 공급된다.** 공개 포스트모템과 프로토콜 스펙은 널려 있고 질이 높다. "다음에 뭐 만들지" 고민이 없다.

## 에피소드 한 편의 구조

```
[진입]       공간 하나. 요청 입자가 흐른다. 제목.
             ↓ 여기서 이미 조작 가능해야 한다 (긴 인트로 뒤에 결과를 숨기지 않는다)

[스크롤 시작] 화면 핀 고정. 이제 스크롤 = 시간.
[장면 1]     정상 — 입자가 일정하게 흐름
[장면 2]     장애 — 원인 발생 → 상태 악화 → 흐름 정지
[장면 3]     완화 — 원인 제거 → 흐름 회복

[스크롤 끝]   핀 해제. 요약 + 원문 근거 링크 + 「제작 과정」 진입점
```

**공간은 하나, 카메라 이동은 없다.** 같은 구도에서 입자·강조·텍스트의 **상태만** 바뀐다.

## 「제작 과정」 페이지 — 이 프로젝트에서 AI 활용의 증거

"AI를 썼다"가 아니라 **"무엇을 맡기고 무엇을 뺏었는가"**를 보여준다.

**중요한 판단 최대 세 건**만 싣는다. 각 건에 묶는 것:

| 항목 | 내용 |
|---|---|
| 입력 요지 | 무엇을 요구했는가 |
| 실제 출력 | AI가 뭘 줬는가 |
| 처분 | 채택 / 수정 / 기각 |
| 이유 | 왜 그렇게 판정했는가 |
| 결과 화면 | 최종적으로 어떻게 됐는가 |

프레이밍은 *"AI를 잡아낸 나"*가 아니라 **"내가 책임지는 동작의 계약"**이다. 어떤 동작을 요구했고, 맞는지 **무엇으로 판정했는가**. 실패가 실제로 있었으면 쓰고, **없었으면 지어내지 않는다.**

> 기록은 사후에 복원되지 않는다. 버린 후보와 그 이유는 나중에 기억나지 않는다. **각 작업 구간 끝에 기록 단계를 넣지 않으면 이 페이지는 지어낸 글이 된다.**

## 소재 선택 기준

1. **시간 축이 본질인가** — 모션이 설명에 기여하는가, 발리는가
2. **다음 걸 또 만들고 싶은가** — 직업적 관심까지는 필요 없다
3. **명료성으로 승부 보는가** — 미감이 아니라

후보 풀:
```
커넥션 풀 고갈 · 데드락 · MVCC 스냅샷 격리 · 2PC
Kafka 파티션 리밸런싱 · 캐시 스탬피드 · 백프레셔
TCP 혼잡 제어 · Raft 리더 선출 · TLS 핸드셰이크
실제 장애 회고 (Cloudflare 2019 처리 고갈, 2020 백본 경로 집중 등)
```

제외한 축:
- **CS 기초(자료구조·알고리즘)** — visualgo 등 기존 시각화가 포화. 희소성 없음
- **AI 논문** — 시간 축이 본질인 게 일부뿐, 오독 위험 큼, BE 정체성과 멂

## 배포

**개인 사이트가 본진. 유튜브/SNS는 완성된 페이지의 녹화본을 던지는 창구.**

순서를 거꾸로 하면 안 된다. 영상이 목표가 되면 제작이 영상 우선이 되고, 역스크롤 상태 일관성·reduced-motion·모바일 대응처럼 **영상에 하나도 기여하지 않는 것들**이 빠진다. 그게 빠지면 남는 건 explainer 영상 제작자다.

1회차에서는 유튜브를 신경 쓰지 않는다. 녹화는 완성 후 15분이면 된다.

## 현재 상태

- [ ] 1회차 소재 확정
- [ ] 첫 작업 구간 (8시간) — 대표 전환 하나 작동
- [ ] 모바일 표시 + 정적 단계 보기
- [ ] 「제작 과정」 페이지
- [ ] 공개
- [ ] 2회차 전환 하나 이식 실험

### 첫 작업 구간 (8시간) 배분

| 시간 | 작업 |
|---|---|
| 1h | 원문에서 화면에 쓸 주장 3개와 근거 위치 선정 |
| 1h | AI로 장면 구성·이미지 후보 생성, 미술 방향 하나 선택 |
| 4h | 정상↔장애 대표 전환 하나를 브라우저에서 작동 |
| 1h | 모바일 표시 + 정적 단계 보기 최소 경로 |
| 1h | 왕복 조작 확인 · 내용 대조 · **실제 판단 기록** |

**성공 판정:** "정상과 장애가 구분되고, 되돌려도 깨지지 않는 장면을 다시 열 수 있음."
전체 사이트도, 완성된 회차도, 범용 엔진도 요구하지 않는다. 시간은 작업별 **상한**이지 완료 보장이 아니다.

## 명시된 가정과 한계

- **이 설계는 지속성을 보장하지 않는다.** 1회차 완성과 2회차 전환 이식은 지속 가능성을 **시험**하는 근거이지 장기 지속의 **입증**이 아니다.
- **월 2만원 / 1회차 총 40시간 / 후속 4시간**은 임시 예산과 검증 목표다. 확정 조건도, 보장된 공수도 아니다. **목표를 지키려고 검수와 기록을 줄이지 않는다.**
- **주제 관심은 미검증 가정이다.** 원문을 읽었을 때 "이 장면을 내 손으로 설명해보고 싶다"가 들지 않으면 같은 제작 방식으로 다른 소재로 교체한다.
- 2026년 채용 시장에서 어떤 신호가 실제로 유효한지는 검증된 근거가 없다. 위 판단은 전부 가설이다.
